## 四、固件命名规则

### 4.1 文件名格式

```
<设备型号>_<版本号>.trx
```

例如 `K2P_DRV_V5_3.4.3.9-099.trx`、`RT-AC51U_3.4.3.9-099.trx`。

**同一型号在不同日期编译的固件文件名完全相同** —— 因此**判断是否为同一版本只能靠内容哈希**，文件名与大小均不可靠。

### 4.2 版本号后缀变体

| 后缀 | 含义 |
|---|---|
| （无后缀） | 标准版 |
| `_8M` / `_16M` | 对应闪存容量版本 |
| `_接口反转千兆WANLAN` / `_接口正常顺序百兆WAN` | 网口顺序适配 |
| `_原厂8M闪存（基础版）-WAN/-LAN` / `_已换16M闪存（完全版）-WAN/-LAN` | 按闪存与网口区分 |

> 完整后缀统计见 [附录 C](#附录-c版本号后缀统计)。

### 4.3 源站目录编号说明

- 源站历史归档目录形如 `padavan_YY-MM-N`，其中 **`N` 是「月内第 N 次发布」的序号，不是日期**。
- 本镜像已统一整理为 **`padavan_YYYYMMDD`（发布日期）**，故与源站编号不完全对应。

## 七、如何校验与还原

本镜像提供**两层校验**，可分别在下载后、解压后使用：

| 层级 | 文件 | 用途 |
|---|---|---|
| ① **下载前/后** | Release 里的 `MD5SUMS.txt` | 校验**下载到的 zip 包本身**（标准 `md5sum` 格式） |
| ② **解压后** | zip 内自带的 `MD5.txt` | 校验**解压出的每个固件**（MD5 + SHA1 + CRC32 三重） |

### 还原步骤

1. 从对应月份的 Release 下载所需 zip；
2. 用同 Release 的 `MD5SUMS.txt` 校验 zip 完整性：

```bash
# Linux / macOS
md5sum -c MD5SUMS.txt

# Windows（PowerShell）
Get-FileHash -Algorithm MD5 padavan-2023-01__20230105.zip
```

3. 解压 zip（保留内部相对路径）；
4. 用解压目录内的 `MD5.txt` 逐文件核对（该清单含 MD5 + SHA1 + CRC32）。

### MD5.txt 格式（与源站一致）

```
文件：	<文件名>
大小：	<字节数>
MD5：	<32 位大写>
SHA1：	<40 位大写>
CRC32：<8 位大写>
```

## 九、数据来源与说明

| 渠道 | 说明 |
|---|---|
| 源站 `padavan/` | 当前版固件 |
| 源站 `旧文件/` | 历史归档（**源站会清理旧版本**，故本镜像按发布日期完整留存） |
| 源站 `opt-file/`、`opt-script/` | 配套工具与脚本 |

**已知情况**：

- 源站历史归档目录的编号 `padavan_YY-MM-N` 中 `N` 为月内发布序号，本镜像已按**实际日期**重新整理为 `padavan_YYYYMMDD`。
- 源站会**清理历史版本**，较早版本可能已无法从源站取得；本镜像尽量完整留存。
- 作者归档中存在**不同型号内容完全相同**的情况（如 `K2P_DRV_256M` 与 `K2P_DRV_V5`），故**不能按内容哈希去重**。
- 部分固件名带 `_2` 后缀（如 `360P2_3.4.3.9-099_2.trx`），为**作者原始命名**的变体，非重名副本。

## 十、备注

- **打包用 store（不压缩）模式**：`.trx` 多为已压缩格式，压缩无收益。
- **同名固件不同版本**：作者同一型号不同日期的编译产物**文件名恒定**，只有内容哈希能区分。
- **增量更新**：源站发布新版本后，可按相同的打包方式在**对应月份 Release 追加资产**，并更新 `MANIFEST.csv`。
