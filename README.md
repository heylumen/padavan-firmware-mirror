## 固件归档组织方式

固件按**发布年月**建立 Release，tag 采用中文（如 `2023年01月`）。

```
Releases
├── 2022年04月  →  padavan-2022-04__20220401.zip
├── 2022年05月  →  padavan-2022-05__20220501.zip
├── 2022年06月  →  padavan-2022-06__20220601.zip
│                  padavan-2022-06__20220602.zip
├── 2023年01月  →  padavan-2023-01__20230101.zip
│                  … （该月共 5 个版本）
└── …（共 28 个 Release / 36 个版本资产）
```

**资产命名规则**：`padavan-<年>-<月>__<发布日期>.zip`

> 若某月仅有一个版本，该版本即代表整月内容；含多个版本时，各自独立打包为资产，同属该月 Release。

## 完整性校验

每个固件版本目录内均含 `MD5.txt`，格式与源站一致：

```
文件：	<文件名>
大小：	<字节数>
MD5：	<32 位大写>
SHA1：	<40 位大写>
CRC32：<8 位大写>
```

解压后逐文件比对即可验证完整性。

## 版本命名说明

- 本地目录统一命名为 `padavan_YYYYMMDD`（发布日期）。
- 源站原始编号形如 `padavan_YY-MM-N`，其中 **`N` 为「月内第 N 次发布」的序号，并非日期**。本镜像已按实际日期整理归档，故与源站编号不完全对应。
